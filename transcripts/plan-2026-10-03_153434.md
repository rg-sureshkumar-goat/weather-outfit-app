**Tech stack: Which build setup should the app use?**

  - **Vite + plain JS (Recommended)**: A local dev server and npm packages for MediaPipe. It splits the code so Today never loads the vision models (R37). Vitest runs the threshold tests (R8, R13). A GitHub Actions workflow deploys the build to Pages. One state object plus render functions covers R7 without a framework.
  - **No build step**: Plain HTML, CSS and JS modules served as-is, deployed straight from the branch. This has the fewest moving parts. The trade-off: MediaPipe files have to be copied in by hand, and the rule tests need a separate runner.
  - **Vite + a UI framework**: Preact or Svelte, which redraws the screens automatically when the state changes. It's more to set up and debug, and it adds download size.

**Build order: In what order should the checkpoints go?**

  - **Core first (Recommended)**: Weather, state, rules and Today first, using starter outfits and a hand-set avatar, then an early deploy. Closet next, then the selfie and cut-out features. Every checkpoint gives you a working app you can deploy. Both vision features already passed feasibility tests, so their risk is lower.
  - **Riskiest parts first**: Selfie reading and garment cut-out go first, while there's the most time to fix them. Today and the weather flow come later, so the first deployable app arrives later.
  - **First-run order**: Build the screens in the order a new User meets them: selfie, review, location, Today, then Closet and Add item.

**Art timing: When should the final artwork be made?**

  - **Early rounds alongside code (Recommended)**: The character base and the 12 garment templates get art-direction rounds early, because their layer structure shapes the recoloring code. Icons, backdrops and the closet rack follow in later checkpoints. Each round waits for your approval.
  - **Placeholders, then one art pass**: Build everything with grey wireframe shapes, then swap in all the final art in one checkpoint near the end. Coding goes faster, but you risk rework if the final art doesn't fit the placeholder layers.
  - **All art before code**: Finish and approve every asset first. The art is settled up front, but nothing works until late.
